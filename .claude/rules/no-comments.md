# Код без комментариев

Go (включая тесты), shell-скрипты, hook в `.githooks/` и `.gitleaks.toml` пишутся без комментариев (ADR 0005), `scripts/check.sh` это проверяет и печатает находки строками `путь:строка: текст`. Смысл, который хочется пояснить, и знание из удаляемого комментария уходят в первое подходящее место:

1. **Имя.** Переменная, константа или функция называют то, что делают. Аргументы shell-функции получают имена локальных переменных в её первой строке: `local file=$1 line=$2`.
2. **Тест**, имя которого называет причину неочевидного поведения: через `Run` для `gms`, случай `blocked`, `passes` или `hook_case` в `scripts/check-secrets.sh` для скриптов, hook и `.gitleaks.toml`.
3. **ADR** для решения с выбором, **README** для поведения, видимого пользователю, **`CODING_STANDARDS.md`** для правила, как писать код или тесты.
4. **`internal/gms/testdata/README.md`** для заготовок ответов GitLab: дата съёмки реальной, из какой заготовки и какой правкой собрана синтетическая.
5. Остальное удаляется, контекст остаётся в сообщении коммита.

Директивы инструментов пишутся как есть, без пояснений: `//go:…`, `//nolint…`, `// gitleaks:allow` и shebang в первой строке скрипта. Строка данных в heredoc и в многострочном литерале TOML начинается с любого символа, кроме `#`: shebang записываемого файла выводится отдельной командой, `{ echo '#!/bin/sh'; cat <<'EOF'; } >файл`.
