Задача 8:

Нужно публиковать готовые бинарники `gms` в GitHub Releases, чтобы его можно было поставить без Go.

Зачем: README говорит «Готовых бинарников нет», и `gms` ставится только через `go install`. Поэтому каждому
пользователю нужен Go 1.27+, хотя Go нужен только для сборки.

Что известно:
- Платформы из README: macOS, Linux и Windows, amd64 и arm64. cgo не используется, так что всё собирается
  кросс-компиляцией через `GOOS` и `GOARCH`.
- Репозиторий публичный, тегов и релизов пока нет.
- Флага версии у `gms` нет: `gms -version` из списка улучшений не выбран.
- Бинарники будут без подписи. macOS помечает файл, скачанный браузером, карантином, и Gatekeeper не запустит его без
  `xattr -d com.apple.quarantine` или разрешения в настройках. Антивирус на рабочих машинах проверяет неподписанные
  бинарники при каждом запуске (ADR 0003, там речь о `glab`). `gms` запускается один раз на вывод, так что это,
  вероятно, некритично.
- Тесты пути к конфигу на Windows, судя по коду, не пройдут (задача 4), то есть Windows-сборку тесты не проверяют.

Открытые вопросы:
- Чем собирать: GoReleaser или свой workflow с матрицей `GOOS`/`GOARCH`.
- Схема версий и тегов (например, `v0.1.0`) и что запускает релиз: push тега или ручной запуск.
- Архивы или голые бинарники, нужен ли файл контрольных сумм.
- Встраивать ли версию в бинарник при сборке, раз флага версии нет.
- Как описать установку в README: скачать, положить в `PATH`, снять карантин на macOS. Нужны ли Homebrew tap и Scoop.
- Прогонять ли `scripts/check.sh` перед сборкой релиза.
