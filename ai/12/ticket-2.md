# 2: JSON-служебные сообщения

**What to build:** Весь служебный вывод `gms` — JSON-объекты единого конверта: `error` всегда, опциональные `hint`, `known`, `path`, `example`, `usage`, `config` — по ситуации, с `omitempty`. Справка `-h` — объект с текстом справки в stdout, код `0`; путь к конфигу `-c` — объект с путём в stdout, код `0`. Ошибки разбора флагов и лишних аргументов — `error` с текстом справки в stderr, код `2`. Неизвестные коды и имена окружений — `error` со списком `known`, отклонение до запросов, код `2`. Отсутствие файла конфига — `error` с путём и примером конфига в stderr, код `1`. Не найден или не залогинен glab — `error` с подсказкой входа в stderr, код `1`, stdout пустой. Тексты сообщений и момент выбора кодов выхода прежние, меняется только форма.

**Blocked by:** None (может стартовать сразу; рекомендован после тикета 1, так как оба правят слой вывода)

**Status:** ready-for-agent

- [ ] `gms -h` печатает в stdout объект с текстом справки, код `0`
- [ ] `gms -c` печатает в stdout объект с путём к конфигу, код `0`
- [ ] Ошибка разбора флагов и лишние аргументы печатают в stderr объект с текстом ошибки и текстом справки, код `2`
- [ ] `-p` без кодов и `-e` без имён печатают в stderr объект с текстом ошибки и примером, код `2`
- [ ] Неизвестные коды и имена окружений печатают в stderr объект с текстом ошибки и списком известных значений, код `2`, до любых запросов к GitLab
- [ ] Отсутствие файла конфига печатает в stderr объект с текстом ошибки, путём и примером конфига, код `1`, stdout пустой
- [ ] Не найден или не залогинен glab печатает в stderr объект с текстом ошибки и подсказкой входа, код `1`, stdout пустой
- [ ] Опциональные поля опускаются, когда их нет; тесты наблюдают stderr целиком, ожидания записаны литералами
- [ ] `scripts/check.sh` зелёный
