# 1: Текущий деплой одного проекта: от конфига до вывода

**What to build:** `gms -p project2` при корректном конфиге выводит блок проекта `project2`. Сначала строка с кодом проекта, затем по каждому окружению в порядке конфига: заголовок `<ОКРУЖЕНИЕ>:`, дата деплоя, версия приложения, коммит деплоя. Это первый сквозной путь: конфиг → `glab` → вывод. Только счастливый путь и ровно один код в `-p`. Спека: `ai/1/spec.md`, ADR 0001 и 0002.

Что входит:
- Точка входа `Run(args, deps) → exit code`. `deps` содержит runner `glab`, чтение переменных окружения, stdout, stderr и часовой пояс. Это единственный seam для тестов.
- Чтение конфига из `GMS_CONFIG` или `~/.config/gms/config.json` с сохранением порядка ключей на обоих уровнях.
- Разбор URL ветки окружения на хост, путь проекта в GitLab и ветку окружения.
- Текущий деплой: запрос к Deployments API (`environment` = ключ окружения в нижнем регистре, `status=success`, сортировка по `finished_at` по убыванию, одна запись) через `glab api --hostname <host>`.
- Версия приложения: строка `build_version=` из `application.version` на коммите деплоя.
- Подключение настоящего `glab` и `time.Local` в production-точке входа. Шаблонный `main.go` от GoLand заменяется.
