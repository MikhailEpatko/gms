# 4: Ошибки GitLab: по паре, по версии, отсутствие `glab`

**What to build:** сбой GitLab по одной паре проект+окружение не скрывает остальные пары. Ошибка выводится на месте этой пары, а в конце код выхода 1. Если не удалось получить только версию приложения, дата и коммит всё равно выводятся. Если `glab` не установлен или не залогинен в хост из конфига, утилита сразу завершается с подсказкой и не делает запросов. Спека: `ai/1/spec.md`, user stories 30–33.

**Blocked by:** 1 (Текущий деплой одного проекта: от конфига до вывода)

**Status:** done

- [x] Ошибка запроса текущего деплоя по паре выводится под заголовком окружения одной строкой `ошибка: <причина>`. Остальные окружения и проекты выводятся как обычно. Код выхода 1.
- [x] Ошибка запроса `application.version`, или отсутствие в нём `build_version=`, выводит вместо строки версии `версия: ошибка (<причина>)`. Дата и коммит выводятся. Код выхода 1.
- [x] Если `glab` не найден, утилита до любых запросов к API завершается с ненулевым кодом и сообщением с подсказкой установить `glab`.
- [x] Если `glab` не залогинен в хост из конфига, утилита до запросов к API завершается с ненулевым кодом и подсказкой `glab auth login --hostname <host>`.
- [x] Все проверки идут через `Run` с фейковым runner, который возвращает ошибки для выбранных путей. `go test ./...` проходит.
