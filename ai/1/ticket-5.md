# 5: Ошибки использования и конфига, флаги `-c` и `-h`

**What to build:** неверный вызов или неверный конфиг дают понятную ошибку до любых обращений к GitLab. `-c` показывает путь к конфигу, `-h` показывает справку. Спека: `ai/1/spec.md`, user stories 9–18, 21.

**Blocked by:** 1 (Текущий деплой одного проекта: от конфига до вывода), 2 (Несколько проектов и разбор `-p`)

**Status:** done

- [x] `-c` печатает путь к конфигу и завершается с кодом 0, другие флаги игнорируются, запросов к `glab` нет. По умолчанию путь `~/.config/gms/config.json`, при заданном `GMS_CONFIG` печатается он.
- [x] `-h` выводит справку по флагам.
- [x] Неизвестный код в `-p` даёт ошибку со списком известных кодов и код выхода 2, запросов к `glab` нет.
- [x] `-p` без единого кода (в том числе `-p ,`) даёт ошибку и код выхода 2.
- [x] Позиционный аргумент (`gms -p project1 project3`, `gms project1`) даёт ошибку с подсказкой `-p project1,project3` и код выхода 2.
- [x] Неизвестный флаг даёт ошибку, справку и код выхода 2.
- [x] Отсутствующий конфиг: сообщение «создайте <путь>» и пример конфига с обезличенными URL (`gitlab.example.com`), ненулевой код выхода. Файл не создаётся.
- [x] Битый JSON или URL не вида `https://<host>/<group>/<repo>/-/tree/<branch>` дают ошибку с указанием проекта и окружения и ненулевой код выхода.
- [x] Все проверки идут через `Run` с фейковым runner. `go test ./...` проходит.
