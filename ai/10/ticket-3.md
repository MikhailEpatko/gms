# 3: Скрипты без комментариев, проверка в check.sh, правила

**What to build:** в `scripts/check.sh`, `scripts/check-secrets.sh`, pre-commit hook и `.gitleaks.toml` нет комментариев. Тогда `scripts/check.sh` начинает запускать программу проверки (после `gofmt`, до `go vet`), и комментарий в коде останавливает и `check.sh`, и коммит через hook.

Знание из комментариев скриптов уходит по порядку ADR 0005:
- что делают hook и `check.sh`, уже описано в README и ADR 0004, поэтому шапки скриптов просто удаляются;
- решения внутри скриптов сверяются с ADR 0004 и дописываются туда, если их нет: `.gitleaksignore` не копируется, конфиг gitleaks передаётся явно, у одноразовых репозиториев свой глобальный конфиг git, PATH без gitleaks;
- назначение аргументов shell-функций видно из имён локальных переменных;
- shebang заглушки `check.sh` в heredoc `check-secrets.sh` выводится отдельной командой.

Агент, который правит Go, скрипт, hook или TOML, получает правило о том, куда уходит знание. Ревьюер получает раздел «Комментарии». Документы и связанные задачи приводятся в соответствие. Спека: `ai/10/spec.md`, user stories 13, 31–39, 43, 44, 46, 48.
