# 3: Подсказка для значений через пробел с `-e`

**What to build:** если имена окружений перечислены через пробел (`gms -e DEV DEMO`), `gms` сообщает о лишних аргументах и подсказывает полную исправленную команду (`gms -e DEV,DEMO`). Каждое лишнее слово относится к ближайшему флагу `-p` или `-e` слева от него, а слова, перед которыми ни одного из этих флагов нет, относятся к `-p`, как сейчас. Подсказки для команд без `-e` не меняются. Спека: `ai/2/spec.md`, user stories 27–30.

**Blocked by:** 1 (Фильтр окружений `-e`)

**Status:** done

- [x] `gms -e DEV DEMO` выводит в stderr `gms: лишние аргументы: DEMO` и `окружения перечисляются через запятую: gms -e DEV,DEMO`, exit 2, пустой stdout, без вызовов `glab`.
- [x] `gms -p project1 project3 -e PROD DEV` выводит `gms: лишние аргументы: project3 -e PROD DEV` и `коды проектов и окружения перечисляются через запятую: gms -p project1,project3 -e PROD,DEV`.
- [x] В подсказке сначала идёт `-p`, затем `-e`, и каждый флаг появляется только если у него есть значения. Начало строки зависит от флагов в подсказке: «коды проектов…», «окружения…» или «коды проектов и окружения…».
- [x] `-p` и `-e` в любой записи (`-e x`, `-e=x`, `--e x`) переключают флаг, к которому относятся следующие слова. Другие флаги (`-c`, неизвестные) в подсказку не попадают.
- [x] Значения в подсказке нормализуются по правилам своего флага: разбиение по запятой, обрезка пробелов, пропуск пустых, схлопывание повторов (у `-e` без учёта регистра).
- [x] Прежние подсказки для команд без `-e` выводятся слово в слово как раньше: `gms -p project1 project3`, `gms project1`, `gms project1 -p project3`.
- [x] В `README.md` и `AGENTS.md` подсказка описана с примером для `-e`.
- [x] Все проверки идут через `Run` с фейковым `glab`. `scripts/check.sh` проходит.
