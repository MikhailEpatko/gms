# 1: Hook не пускает коммит с секретом по правилам gitleaks по умолчанию

**What to build:** pre-commit hook первым шагом проверяет индекс gitleaks v8.30.1 и не пускает коммит, если нашёл секрет по правилам по умолчанию (токены провайдеров, приватные ключи, энтропия). В выводе есть файл, строка и `RuleID`, секрет заменён на `REDACTED`, а после вывода gitleaks hook печатает подсказку на русском. Конфиг gitleaks лежит в корне репозитория и пока только расширяет правила по умолчанию, а hook передаёт его явно, так что `GITLEAKS_CONFIG` и текущий каталог на правила не влияют. Без `gitleaks` в `PATH` коммит не проходит, а hook подсказывает команду установки. Без секретов коммит идёт дальше в `scripts/check.sh` как раньше. В README появляются шаги перед первым коммитом, в AGENTS.md правило для агента: hook не обходить, исключения самому не добавлять. Спека: `ai/9/spec.md`, user stories 1, 2, 9–17, 20, 22–31, 33.

**Blocked by:** None (can start immediately)

**Status:** done

- [x] В одноразовом клоне с подключённым hook коммит файла с токеном `glpat-` + 20 символов не создаётся, exit ≠ 0. В выводе есть `File`, `Line` и `RuleID` правила по умолчанию, секрет заменён на `REDACTED`, сам токен не печатается нигде. `check.sh` не запускается.
- [x] После находок hook печатает в stderr подсказку: коммит остановлен, секрет нужно убрать из индекса, а ложное срабатывание оформляется через `gitleaks:allow` в строке или через allowlist правила в конфиге gitleaks.
- [x] Проверяется индекс, а не рабочее дерево: секрет в неиндексированном файле или неиндексированной правке коммиту не мешает, секрет в индексированной версии файла коммит останавливает, даже если в рабочем дереве его уже убрали.
- [x] Если `gitleaks` нет в `PATH`, коммит не создаётся, в stderr выводится `gitleaks не найден, установите: go install github.com/zricethezav/gitleaks/v8@v8.30.1`, exit 1, `check.sh` не запускается.
- [x] Если `GITLEAKS_CONFIG` указывает на конфиг без правил, токен из первого критерия всё равно ловится.
- [x] Если gitleaks завершился с ошибкой не из-за находки (например, конфиг сломан), коммит тоже не создаётся.
- [x] Коммит без секретов проходит в `scripts/check.sh`, и дальше всё идёт как раньше: зелёный `check.sh` даёт коммит, красный его останавливает.
- [x] Комментарий в hook описывает оба шага (секреты по индексу, затем `check.sh`) и то, как подключить hook.
- [x] В README в разделе «Сборка из клона» есть блок перед первым коммитом с командами `git config core.hooksPath .githooks` и `go install github.com/zricethezav/gitleaks/v8@v8.30.1` (альтернатива — `brew install gitleaks`). Там же сказано, что hook не пустит коммит с секретом, а push protection на GitHub — второй рубеж только для токенов известных провайдеров.
- [x] В AGENTS.md строка про hook говорит, что сначала gitleaks проверяет индекс с конфигом из корня, затем запускается `check.sh`. Рядом правило для агента: не делать `--no-verify`, не добавлять `gitleaks:allow` и не менять allowlist самому, при срабатывании остановиться и сообщить пользователю файл, строку и `RuleID` без самого секрета, исключение добавлять только после того, как пользователь подтвердил ложное срабатывание.
- [x] `.gitleaksignore` в репозитории нет, корпоративного домена в конфиге gitleaks нет.
- [x] Если в корне есть `.gitleaksignore`, даже неотслеживаемый, коммит не создаётся, а hook просит удалить файл и называет два допустимых механизма исключений. Отказ срабатывает и при индексе без секретов. Добавлено по ревью: gitleaks сам читает этот файл и молча пропускает находки.
- [x] Полная проверка истории репозитория gitleaks с новым конфигом находок не даёт. `scripts/check.sh` проходит в чистом клоне HEAD с изменениями тикета. В рабочем дереве он падает на незакоммиченных правках `helpers_test.go` и `errors_test.go`, которые к задаче не относятся.
- [x] Fake-секреты для приёмки есть только в одноразовом клоне, в репозиторий они не попадают.
