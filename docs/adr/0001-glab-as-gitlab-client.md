# glab как клиент GitLab

`gms` не ходит в GitLab через собственный HTTP-клиент: каждый запрос выполняется подпроцессом `glab api --hostname <host> ...`, где хост берётся из URL в конфиге. Так авторизацию, хранение токена (keyring) и self-hosted хост берёт на себя `glab`, а в `gms` нет ни токенов, ни переменных окружения для них. Цена решения: `glab` должен быть установлен и залогинен в `gitlab.example.com`, а `gms` перед запросами проверяет это и завершается с подсказкой `glab auth login --hostname gitlab.example.com`.

## Considered Options

- Свой HTTP-клиент и PAT из `GITLAB_TOKEN`: нет внешней зависимости во время работы, но токеном нужно управлять отдельно от `glab`.
- Свой HTTP-клиент и токен из конфига `glab`: отклонён, формат конфига `glab` и хранение в keyring не являются публичным контрактом.
