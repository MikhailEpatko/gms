# Проверка секретов: gitleaks в pre-commit hook, случаи правил в check.sh

Репозиторий публичный, а рядом с кодом живут пароль корпоративного прокси и хост корпоративного GitLab. Поэтому pre-commit hook первым шагом проверяет индекс gitleaks с правилами по умолчанию и двумя своими правилами из `.gitleaks.toml` (`url-credentials`, `gitlab-tree-url`, задача 9). Затем hook запускает `scripts/check.sh` на копии индекса во временном каталоге (`git checkout-index -a --prefix`), а не на рабочем дереве. `check.sh` вызывает `scripts/check-secrets.sh`, который на каждой проверке прогоняет случаи правил, сквозные коммиты через hook в одноразовых репозиториях и все файлы репозитория по текущим правилам.

## Consequences

- `check.sh` и hook требуют gitleaks в `PATH`, CI (задача 4) тоже должен его ставить. Историю репозитория `check.sh` не сканирует: это шаг CI.
- `check.sh` в hook видит только то, что попадёт в коммит. Незастейдженная красная правка коммит не останавливает, а сломанный индекс с исправлением в рабочем дереве останавливает. Файл, нужный тестам, должен быть в индексе.
- Пакет на копии индекса собирается заново (другой путь), и коммит через hook на рабочей машине идёт ~23 с вместо ~12 с. Запуск процесса под Kaspersky стоит ~0,1–0,3 с и параллельно не ускоряется (см. ADR 0003). Поэтому в `check-secrets.sh` совместимые случаи hook собраны в один коммит, а результат проверяется встроенными командами bash.
- Строки случаев в `check-secrets.sh` записаны с `~` вместо `://` и собираются только во временном каталоге, иначе скрипт не прошёл бы свои же правила.
- В macOS `mktemp -d` без шаблона игнорирует `TMPDIR`, поэтому hook передаёт шаблон явно.

## Considered Options

- Ручная приёмка правил (первое решение задачи 9: «регулярки меняются редко»). Отклонена: за один вечер правила переписывались 4 раза, оба раунда ревью нашли обходы (`P@ssw0rd`, апостроф и `$` в пароле, логин в URL, `HTTPS://`), а приёмка из 268 строк осталась в scratchpad сессии.
- Запуск `check-secrets.sh` отдельно, только после правки `.gitleaks.toml`: отклонён, его легко забыть.
- `git stash push --keep-index` вокруг `check.sh`: отклонён, он меняет рабочее дерево пользователя и при застейдженных файлах даёт конфликты при `pop` (так случилось при коммите задачи 9).
