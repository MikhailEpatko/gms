# JSON как единственный формат вывода

Весь вывод `gms` — JSON: отчёт по парам — плоский массив объектов в stdout, служебные сообщения — объекты с `error` и опциональными полями в stderr. Текстового формата и флага выбора формата нет. Текстовые строки парсились хрупко: поля склеены пробелами, заголовок коммита не отделяется от пометки, а пометки `(MR !N)` и `(ветка: X)` — вывод за пользователя, а не данные. Формат один, потому что он одинаково читаем и глазами (отступы в два пробела), и машиной (`jq`) — флаг выбора добавил бы абстракцию без второго формата.

Схема отчёта плавающая: известное заполнено, неизвестное опущено (`omitempty`). Поле `error` — единый слот состояния пары: строка `Нет деплоев` или причина сбоя пары и версии. `Нет деплоев` — не сбой: критичность читается только из кода выхода (`1` — есть сбой пары или версии, `0` — все пары ответили). Ветка деплоя в отчёт не передаётся: сравнение с веткой окружения — ответственность потребителя, поэтому запрос GraphQL больше не читает `ref`, а разбор `refs/merge-requests/` и пометка удалены. HTML-экранирование JSON выключено: заголовки коммитов с `<`, `>`, `&` остаются читаемыми.

## Consequences

- Потребители разбирают вывод по именам полей. Добавление поля — совместимое изменение, переобозначение или удаление — ломающее: форматом начинают пользоваться скрипты сразу, откат дорогой.
- Состояние пары читается из `error` вместе с данными, а не из текста вне документа; отличие «ошибка версии» от «ошибки пары» — по наличию `deployed_at`.
- Служебные объекты (`usage`, `config`, `error` + `hint`/`known`/`path`/`example`) — отдельный конверт, не конверт отчёта: корень отчёта остаётся массивом, `jq '.[]'` работает без префикса.

## Considered Options

- Текст по умолчанию и JSON по флагу (`-json`, `-o json`): отклонено — формат один, второго нет и не планируется (grilling-сессия задачи 12, Q1).
- Вложенный объект «проект → окружение → деплой»: отклонён — объект в JSON неупорядочен, а порядок вывода «как в конфиге» — заявленное поведение; массив сохраняет его бесплатно (Q2).
- Стабильный набор ключей с `null`: отклонён в пользу `omitempty` — минимальный документ без пустот (Q3).
- Дата как в тексте (`2006-01-02 15:04:05 MST`): отклонена — `MSK` не смещение, RFC 3339 парсится стандартными средствами (Q4).
- Поля `ref`, `mr`, `version_error`: показаны в черновике формата, убраны по решению пользователя — все сбои живут в одном `error`, а внутреннее устройство ссылок GitLab в формате не раскрывается.
- Компактный JSON без отступов: отклонён — вывод чаще смотрят глазами, а `jq` не различает (Q5).
